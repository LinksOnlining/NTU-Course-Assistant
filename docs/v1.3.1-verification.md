## 冻结的时间语义

- `startPeriod` 与 `endPeriod` 同时存在：`PERIOD_BASED`。唯一时间事实是星期、节次、周次；当前实际钟点只能由节次索引和当前已确认的 `PeriodTime[]` 解析。
- 两个节次索引同时为空：`FIXED_TIME`。此时 `startTime/endTime` 才是实际时间。
- 两个索引不成对：数据无效，不能默认为固定钟点。
- 为兼容 schema 5 和既有行，`PERIOD_BASED` Course 仍保存 `startTime/endTime` 快照；运行时绝不以其回退。作息缺失或节次无法映射时不显示旧钟点、不生成基础 occurrence，但保留课程原行，待作息有效后可再次解析。
- 手动固定钟点课程不随作息变化；明确钟点的 RESCHEDULE / MAKEUP 保持固定；仅换教室与停课仍作用于当前解析出的基础 occurrence。

## 端到端数据路径核对

```text
PDF coordinate parser
→ ImportCandidate.weekday/startPeriod/endPeriod/weeks
→ evaluateImportCandidates / prepareCourseProposal
→ materializeImportCourses（保留候选节次索引）
→ import_courses
→ SQLite start_period/end_period
→ row_to_course / load_courses
→ getCourseTimeMode + resolveCourseTime
→ CourseOccurrence / timetable / Today / Widget / Reminder
```

- `src/importers/ntu-pdf/parse.ts` 识别星期/节次/周次，不根据节次生成时钟事实。
- `src/core/import-proposal.ts` 只用已确认作息将候选暂时解析成导入兼容钟点，并在最终 materialize 时重新校验且保留 `startPeriod/endPeriod`。
- Rust `import_courses`、SELECT 和 `row_to_course` 均持久化并回读 `start_period/end_period`；新增隔离 SQLite 测试覆盖导入、换作息、关闭重开后节次索引仍在且课程行未被改写。
- 生产展示的时间来自 `src/core/period-time.ts::resolveCourseTime`。`App.tsx` 在课程/提醒路径将结果合并为有效数据；`course-occurrence.ts::baseOccurrence` 只以该 resolver 产生 occurrence；Widget 同样解析后再构建视图。`CourseCard` 的节次标签直接显示课程节次索引，不再通过钟点反推。
- 作息保存更新 `periods` state，触发 `effectiveUserCourses` 与 canonical occurrence 重算；无有效作息的 PERIOD_BASED 课程不进入可显示列表。没有作息保存路径遍历或 UPDATE 全部课程。
