## 根因与数据语义

v1.3.0 PDF 导入的课程行同时保存 `startPeriod/endPeriod` 和导入时作息派生的 `startTime/endTime`。解析 `CourseOccurrence` 时只读取旧钟点，没有将节次索引与当前作息结合，因此作息修改后课程仍显示旧时间。

修复后，成对存在的节次索引表示 PERIOD_BASED，effective time 由 `PeriodTime[]` 解析；两个索引均为 null 表示 FIXED_TIME，继续使用课程保存钟点。旧 v1.3.0 数据本身已有索引，按新 resolver 读取即可，不回写或批量修改课程数据。没有保存节次映射时保留现有钟点作为兼容显示回退。

明确钟点的 RESCHEDULE / MAKEUP 仍为单次固定时间；仅换教室与取消继续采用按当前作息解析的基础安排。课程原始存储钟点不因作息保存而批量更新。

## 统一消费路径

- 全周课表：PeriodTime 改变后重新派生用户课程钟点。
- 今日与课程变化：通过 `resolveCourseOccurrences` 获得当前钟点。
- Widget：Native Widget 数据加载包含 PeriodTime；有学期时使用 canonical occurrence，无学期兼容路径也先解析节次课程。
- Reminder：作息变化进入计划构建依赖，重新解析课程并重建提醒计划。
- 课程编辑：显示当前派生钟点；未改钟点时保留原节次索引，改动钟点时保存为固定钟点课程。
