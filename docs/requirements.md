# 大学课程表程序开发提示词

你现在是这个项目的**唯一主开发工程师**，负责需求分析、架构设计、编码、测试、Debug、重构、文档维护、Git 管理、构建和阶段性工程审查。

我要开发一款面向大学生使用的 **Windows 11 桌面课程表程序**。

# 一、开发原则

这是一个需要长期迭代的正式项目，不是一次性 Demo。

## 最重要的原则

**绝对不要一开始就把整个程序全部写完。**

必须采用：

> 大阶段 → 小阶段 → 实现 → 验证 → 修复 → PASS → 下一阶段

的渐进式开发方式。

每完成一个小功能，都必须进行针对性的验证。

如果验证失败：

1. 自动分析原因；
2. 修复问题；
3. 再次测试；
4. 直到验证 PASS；
5. 才允许进入下一步。

不要因为后续功能已经规划好，就提前一次性实现。

# 四、核心功能 1：课程表

程序必须有课程表主界面。

每门课程至少需要支持：

* 课程名称
* 教师
* 教室
* 星期
* 开始节次
* 结束节次
* 开始时间
* 结束时间
* 上课周数

后续可以增加更多字段，但第一阶段不要过度设计。

---

# 五、课程表 UI 要求

课程表不能采用简单的：

> 一门课紧挨一门课

这种布局。

必须按照**真实上课时间轴**显示。

例如：

08:00
↓
第一节课

08:50
↓
课间

09:00
↓
第二节课

……

课程卡片的位置和高度应尽可能对应真实时间。

如果两节课程之间存在较长空闲时间：

**UI 上必须明显留出间隔。**

例如：

上午有课

10:00 下课

下午 14:00 才上课

那么课程表中：

10:00 ～ 14:00

应该存在明显的空白区域。

不要把上午课程和下午课程直接挤在一起。

---

# 六、UI 风格

整体 UI 目标：

* 简洁
* 现代
* 清晰
* Windows 11 风格
* 信息层级明确
* 不拥挤
* 不花哨
* 长时间使用不会视觉疲劳

课程卡片需要清楚显示：

**课程名**

其次显示：

* 教室
* 教师
* 时间

不要在一张课程卡片上塞过多文字。

优先保证课程名称和时间的可读性。

---

# 七、核心功能 2：PDF 课程表识别

程序需要能够导入学校提供的课程表 PDF。

第一阶段目标：

> PDF → 提取课程信息 → 用户确认 → 导入课程表

不要一开始追求支持所有 PDF。

首先针对：

**南通大学课程表 PDF**

进行适配。

处理流程应该设计为：

PDF 文件
↓
读取 PDF
↓
提取文字 / 表格
↓
识别课程信息
↓
转换成统一课程数据
↓
显示“导入预览”
↓
用户检查
↓
确认导入
↓
写入本地课程表

必须有：

**导入预览**

不能识别完成以后直接修改正式课程表。

识别失败时应该告诉用户：

* 哪些课程识别成功；
* 哪些课程存在异常；
* 哪些字段无法确定。

不要为了导入成功而编造数据。

---

# 八、核心功能 3：南通大学教务系统导入

除了 PDF，我希望以后可以：

> 直接从南通大学教务系统导入课程表。

但这个功能可能涉及：

* 登录状态
* Cookie
* iframe
* API
* HTML
* 网络请求
* 身份验证

因此：

**当前不要立刻实现完整自动登录。**

第一步先研究南通大学现有系统。

重点研究：

* 南通大学学生课表查询入口；
* 页面如何获得课程数据；
* 是否存在课程表 API；
* 是否可以读取当前浏览器已经登录后的数据；
* 是否可以导出 HTML / JSON；
* 是否可以使用更简单、安全、稳定的方法导入。

优先级：

1. 官方接口 / 可直接获得的数据
2. 已登录页面数据
3. HTML 导入
4. PDF 导入
5. 最后才考虑复杂浏览器自动化

不要尝试绕过学校身份验证。

不要保存学生账号密码。

---

# 九、统一课程导入架构

不要分别为 PDF 和教务系统设计两套完全独立的数据结构。

应该设计类似：

PDFImporter

NTUImporter

FutureImporter

↓

统一转换成：

Course

或其他合理的统一课程模型。

也就是说：

**数据来源可以不同，但是进入程序后的课程数据格式必须统一。**

这样以后才能继续增加：

* Excel
* 图片课表
* 其他大学
* 手动录入

而不需要重写整个课程表系统。

# 十、核心功能 4：开机自启动

程序必须支持 Windows 11：

**开机自动启动。**

设置中提供开关：

开机自启动：

* 开
* 关

默认建议：

关闭。

用户主动开启后才启用。

必须能够：

* 正确注册自启动；
* 正确取消自启动；
* 检测当前自启动状态；
* 重启程序后状态保持一致。

不要为了实现这个功能对 Windows 做不必要的系统级修改。

---

# 十一、核心功能 5：上课提醒

程序需要在每堂课开始前提醒用户。

第一版本先支持一个简单规则：

例如：

> 上课前 15 分钟提醒。

提醒内容类似：

课程名称
上课时间
教室

使用 Windows 系统通知。

例如：

机械设计基础

15 分钟后上课

地点：教学楼 3-201

---

后续可以支持：

* 5 分钟
* 10 分钟
* 15 分钟
* 30 分钟
* 自定义

但第一阶段不要一次实现大量复杂提醒规则。

---

# 十二、提醒准确性

提醒不能简单按照“第几节课”猜测时间。

需要建立：

> 节次 → 实际时间

的对应关系。

例如：

第 1 节：08:00–08:45

第 2 节：08:50–09:35

……

具体时间以后根据南通大学教学作息表确定。

这部分必须设计成可以修改的配置，而不是把时间全部硬编码在业务代码里面。

---

# 十八、测试要求

不要只因为代码没有报红就认为功能完成。

根据模块进行真实测试。

例如：

### 课程表 UI

验证：

* 上午课程位置是否正确；
* 下午课程位置是否正确；
* 中间空闲时间是否显示；
* 连续课程是否正确；
* 不同课程是否重叠；
* 长课程名称是否破坏布局。

### PDF

准备真实或测试 PDF。

验证：

* 文件是否能够打开；
* 内容是否读取；
* 课程是否正确识别；
* 异常数据是否标记；
* 是否能够预览；
* 用户取消后是否不会写入正式数据。

### 提醒

验证：

* 提醒时间计算正确；
* Windows 通知能够出现；
* 已结束课程不会提醒；
* 重启程序以后规则仍正常。

### 自启动

验证：

* 开启成功；
* 关闭成功；
* 状态读取正确。
